## Ordered steps
1. Önce sahte HTTP yanıtlarıyla 403’ün bugün NotFound’a çevrildiğini gösteren regresyon testi ekle.
2. Domain/application katmanlarında `ProviderError` durumunu ekleyip orkestrasyonun bu durumu korumasını sağla.
3. Nominatim adaptöründe yalnızca 200 boş sonuçları NotFound kabul et; HTTP hata kodunu ayrıntı sızdırmadan logla ve sağlayıcı hata sonucunu dön.
4. Controller’da sağlayıcı hatasını generic 502 ProblemDetails’e eşle; 403 gövdesini yanıta/loglara koyma.
5. Entegrasyon testleriyle 502/ProblemDetails ve auth başarısızlığında sağlayıcı çağrısının yapılmadığını doğrula.
6. `scripts/check` çalıştır; bu ortamda `sh` yoksa karşılık gelen build/test adımlarını doğrudan çalıştırıp sınırlamayı kaydet.

## Risks & open questions
- `OutcomeStatus` routing ve geocoding tarafından ortak kullanılıyor. Öneri: yeni durumu yalnızca geocoding akışında kullan, routing’in mevcut davranışını değiştirme.
- Upstream 403 yapılandırma hatası veya kalıcı IP engeli olabilir. Öneri: 502 dön ama otomatik retry yapma; kullanıcıya User-Agent/sağlayıcı politikasını ayrıca düzeltmesini söyle.
- API hata gövdesinin içeriği hassas upstream ayrıntısı taşıyabilir. Öneri: istemciye sabit, genel bir ProblemDetails mesajı ver; HTTP durumunu sunucu logunda tut.

## Plan amendments (R-07)

- 2026-09-26 — **Davranış değişikliği (spec 0004):** sağlayıcı HTTP hata eşlemesi değişti. Geçici olmayan HTTP hataları (ör. 403) artık `NotFound` değil `ProviderError`; orkestrasyon bu durumu ve geçici hatayı `ProviderUnavailable` (502) olarak korur. Bu nedenle mevcut `NominatimGeocodingProviderTests.GeocodeAsync_when_not_found_status_maps_to_not_found` testi spec gereği `GeocodeAsync_when_http_error_maps_to_provider_error` olarak güncellendi; assert zayıflatılmadı, beklenti spec 0004 AC-2/AC-3 doğrultusunda düzeltildi.
- 2026-09-26 — Doküman güncellemesi: `docs/architecture.md` ve `docs/conventions.md` beklenen sonuç tipi listesine `ProviderError` eklendi (plan dosya listesinde yoktu; DoD "dokümanlar güncellendi" kapsamı).
