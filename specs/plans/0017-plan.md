## Diagnosis
The user reproduced the issue with identical venue name and country across the single-hotel and multi-hotel requests: the event pin remained wrong only on the multi-hotel map. Venue geocoding is independent of hotel count, while `StaticMapProjection.Fit` changes zoom and center as hotel bounds change. The 256-to-512 scale change was considered, but Geoapify does not document its Static Maps logical world-pixel scale, and the independent reviewer found the proposed test insufficient to establish that behavior. Recommendation: use Geoapify's documented native marker parameter for the event coordinate so the basemap provider performs that projection itself; keep hotel badges in the existing overlay.

Follow-up diagnosis: the latest wide-coverage PDF shows no visible event pin and hotel badges shifted away from their real basemap locations. The hosted event marker uses Geoapify's coordinate placement, but hotel badges still use the app's local 256-pixel Mercator projection, whose alignment with Geoapify's chosen center/zoom is unverified. Geoapify's official Static Maps guide documents that POST markers without explicit `center` or `zoom` cause the API to frame marker locations automatically, and that marker definitions support text and styling. User approved the amendment on 2026-10-06: send the venue and every hotel badge as native Geoapify markers; omit `center` and `zoom`; disable local venue and hotel marker drawing for the hosted basemap. Keep schematic rendering and hidden hosted route lines unchanged. This uses one marker credit per venue/hotel marker.
