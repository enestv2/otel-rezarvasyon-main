## Ordered steps
1. Plan approval is required before implementation.
2. Verify request prices are caller-provided amounts and there is no verified quote indicator; use explicit PDF disclaimer accordingly.
3. Implement three server-determined policies: budget = lowest comparable nightly price; transport = measured road time then road distance, with clearly labeled straight-line fallback only if no road result; balance = best transport among hotels priced at most 10% above the comparable minimum.
4. Treat <=10% as a small price gap and >10% as significant. Generate savings and transport trade-off statements from compared hotels' actual values.
5. Include walking route metrics only if actually returned. Present them as a separate travel mode in explanations; never compare walking values as though they were road measurements.
6. Suppress budget/balance price selection and gap claims for mixed currencies. Keep the displayed amount and currency for each candidate; do not convert.
7. Render concise Turkish rationales from server-computed allowed reason codes and canonical values, sharing metric formatting with the PDF table. Keep all LLM-generated free prose excluded.
8. Add/update unit and PDF integration tests for all criteria without weakening/deleting existing assertions; verify JSON API response compatibility.
9. Independent read-only review; run `scripts/check`; map proof to each criterion and ship only if all gates pass.

## Risks & open questions
- Equal exact price and route metrics may leave multiple equivalent hotels. Recommendation: use the existing deterministic hotel-name ordering as final tie-break and state that rule only when it decides.
- Some hotels have road routes while others have only straight-line estimates. Recommendation: road data outranks straight-line only when route fallback is needed; never describe straight-line as road distance/time.
- Walking routes may only exist for a subset of hotels. Recommendation: present only available walking measures and state when none are available; do not infer missing values.
- Prices can use different currencies. Recommendation: withhold cross-currency comparison and price-dependent option; no exchange conversion.
- API does not identify confirmed booking rates. Recommendation: label all supplied amounts as request-provided nightly prices, not confirmed reservation prices.
- New three-option content may lengthen PDFs. Recommendation: concise options summary on first page and preserve existing candidate table on following page; avoid duplicating all metrics in prose.
